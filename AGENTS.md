# Инструкция агента проекта

Краткая карта проекта находится в `INDEX.md`. Различай сведения из статьи Co3O4 и результаты анализа измерений по закону Бойля–Мариотта.

## 0. Цель и результаты

Проект проверяет закон Бойля–Мариотта на изотермических измерениях и хранит трехуровневое сжатие проектной статьи:

- `memory/L1.md` — реферат по разделам статьи;
- `memory/L2.md` — 5–10 тезисов, минимум три сверены с исходной статьей и снабжены страницами;
- `memory/L3.md` — однострочное сжатие;
- `INDEX.md` — навигация по проекту и связям между материалами.

## 1. Готовность и проверка

Для результатов недели 2 запускай `python checks/check.py` из корня проекта; код 0 и сообщение «принято» обязательны. Для ДЗ 3 проверь вручную: уровни L1→L2→L3 существуют, в L2 есть не менее трех ссылок на страницы оригинала, `AGENTS.md` содержит не менее пяти содержательных разделов, а все перечисленные файлы доступны из `INDEX.md`.

## 2. Карта и чего агент не может знать сам

- Исходные измерения: `data/measurements.csv`; вычисления недели 1: `src/analyze_boyle.py`; результаты: `results/`.
- Статья пользователя: `library/simonenko_et_al_2022_co3o4.pdf`; PDF-страница 1 соответствует журнальной странице 1728, последняя (9-я) — странице 1736.
- Не смешивай размер ОКР Co3O4 по рентгеновским данным (17 ± 2 нм) с размером частиц по ПЭМ (23 ± 2 нм): это разные измеряемые величины и они описаны на разных страницах.
- Статья предлагает потенциальное применение порошка/чернил для электродных структур планарных суперконденсаторов, но не сообщает испытаний готового устройства. Не приписывай работе измеренную емкость или иные характеристики такого устройства.
- В статье описаны конкретные условия синтеза и печати; не дополняй их предположениями, если параметр не приведен в оригинале.
- Происхождение и погрешность измерений в CSV не описаны; не выводи из него точность прибора или причины ошибки строки 7.

## 3. Инструменты и среда

Для таблиц и численных проверок используй Python 3 и стандартную библиотеку. В PowerShell проверь `python --version`: на этой машине команда может указывать на старый Python из MGLTools; в таком случае используй установленный Python 3.13. Не добавляй зависимости ради простых преобразований Markdown/CSV.

## 4. Запреты

- Не изменять `data/measurements.csv` и `checks/check.py`. `[среда]`
- Не перезаписывать исходную статью в `library/`; хранимую копию защищает атрибут «только чтение», а производные сводки находятся в `memory/`. `[среда]`
- Не менять данные недели 1 и независимую проверку недели 2; файлы `data/measurements.csv` и `checks/check.py` защищены от записи. `[среда]`
- Не приписывать статье испытания готового суперконденсатора и не смешивать размер ОКР с размером частиц. `[окно]`
- Не обращаться к внешним сервисам и не устанавливать пакеты без отдельной необходимости и согласования. `[окно]`

## 5. Режим работы

Работай ReAct: сначала читай `INDEX.md`, затем нужный первоисточник и только связанные файлы. Для каждого тезиса сохраняй ссылку на страницу оригинала; числа пересчитывай отдельно, если они важны для результата. Не дублируй статью в контекст целиком, если достаточно нужных разделов.

## 6. Память

`memory/L1.md`, `memory/L2.md` и `memory/L3.md` — последовательные уровни сжатия одной и той же статьи, а не три независимых пересказа. При изменении L1 перепроверь зависимые тезисы L2 и строку L3. В `diary.md` добавляй дату, запрос, измененные файлы и выполненные проверки; старые записи не переписывай.

## 7. Остановка

Остановись и сообщи человеку, если для утверждения нет страницы в оригинале, вычисления противоречат данным, обнаружен иной источник/версия статьи или для продолжения требуется менять исходные данные либо проверку. Не коммить и не публикуй изменения без отдельного указания человека.

## 8. Граф проекта

Онтология проекта хранится в `ontology.yaml` (корень); заметки графа — в `ontology/notes/`, настройки хранилища — в `.obsidian/`.

- **Классы**: ПроектнаяСущность, НаучнаяСущность, Материал, Метод, Параметр, Феномен, АртефактПроекта, Файл, Задача, ВыполненнаяЗадача. Иерархия задаётся через `parent`.
- **Отношения**: каждое отношение в `ontology.yaml` имеет `domain` и `range`, которые должны ссылаться на объявленные классы.
- **Экземпляры**: каждый объект имеет `kind: instance`, `instance_of` и отдельную заметку с wikilink на класс; классы имеют `kind: class` и не записываются как экземпляры.
- **Правила**: R1 — допустимый статус задачи; R2 — диапазон страниц; R3 — проверка domain/range; R4 — вывод `ВыполненнаяЗадача` по статусу; R5 — незакрытая подзадача блокирует завершение родителя.
- **Заметки**: `ontology/notes/` — отдельная markdown-заметка для каждого класса, экземпляра и отношения. YAML frontmatter: `type: class` / `type: instance` / `type: relation`. Wikilinks на классы и связанные узлы.
- **Граф**: мини-граф содержит не менее 10 объектных узлов; узлы и связи должны быть согласованы с иерархией и domain/range онтологии.
- **Obsidian**: `.obsidian/` содержит настройки локального хранилища и graph view.
- **Типизация**: классы ≠ экземпляры. Классы имеют `parent`, экземпляры — `instance_of`. Отношения строго согласованы с domain/range.

## 9. Задачи

Задачи хранятся в `tasks/`. Каждая — markdown-заметка с YAML frontmatter:

- `type: instance`, `instance_of: Класс_Задача`
- `status`: открыта, в работе, выполнена, принята или заблокирована
- `outcome` и `outcome_file` обязательны для статусов `выполнена` и `принята`
- Wikilinks на классы и связанные узлы
