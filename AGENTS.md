# AGENTS.md — шаблон

Скопируйте файл в корень своего проекта под именем `AGENTS.md`. На этой
неделе полностью заполняются разделы 0, 1, 4, 5 (режим работы) и 7; в
разделах 2, 3, 6 — по одной-две строки, подробно они пишутся на неделе 3.
Образцы для пяти видов работы — в папке `agents_examples/`.

Файл читается агентом в начале каждой сессии. Правило отбора строк: если
строку убрать, ошибётся ли агент? Если нет — строка лишняя.

Другие агенты читают этот файл под именами `AGENTS.md`, `CLAUDE.md`,
`.cursorrules`, `.goosehints`.

---

## 0. Цель и образ результата

По данным из `data/measurements.csv` проверить выполнение закона Бойля–Мариотта при постоянной температуре.



Нужно создать два файла:



1. `results/week2_boyle.csv` со строкой для каждого исходного измерения и столбцами:

   - `row` — номер строки измерения, начиная с 1;

   - `volume_l` — объём в литрах;

   - `pressure_kpa` — давление в кПа;

   - `pv_kpa_l` — произведение давления на объём;

   - `relative_deviation` — относительное отклонение `pV` от медианы;

   - `is_outlier` — `true`, если абсолютное относительное отклонение больше 10%, иначе `false`.



2. `results/week2_summary.md`, где указаны:

   - число обработанных измерений;

   - медиана `pV`;

   - номера обнаруженных выбросов;

   - среднее `pV` без выбросов;

   - относительный разброс без выбросов;

   - краткий вывод о согласии данных с законом Бойля–Мариотта.



Исходные строки в CSV должны сохранять первоначальный порядок. Числовые значения записать с достаточной точностью для независимой проверки.

## 1. Критерий готовности

Работа считается выполненной, если команда

```powershell
python checks/check.py
```

завершается с кодом 0.

Проверка должна независимо подтвердить:

- наличие `results/week2_boyle.csv` и `results/week2_summary.md`;
- совпадение числа и порядка строк с исходными данными;
- правильность значений `pV` и относительных отклонений;
- правильную отметку выбросов по порогу 10%;
- наличие обязательных итоговых величин в отчёте.

Перед окончательным ответом самостоятельно запусти проверку. Если она не
прошла, исправь результат и вызови её повторно. Не изменяй проверку ради
получения кода 0.

## 2. Карта проекта и источники

Исходные измерения: `data/measurements.csv`, столбцы `volume_l`, `pressure_kpa`, `temperature_k`. Скрипт первой недели: `src/analyze_boyle.py`; прежние результаты: `results/pv_table.csv` и `results/summary.json`. Новый результат недели 2 сохраняй в отдельных файлах, указанных в разделе 0. Температура во всех строках постоянна. Выброс отмечается при абсолютном относительном отклонении `pV` от медианы строго больше 10%.

## 3. Инструменты и границы

Доступны Python 3 и стандартная библиотека. Входные данные и проверка защищены от записи. Не устанавливай пакеты и не используй сеть. Для расчетов используй CSV из `data/measurements.csv`; не считай прежний результат первой недели независимым эталоном.

## 4. Запреты

У каждого запрета — пометка, где он обеспечивается. Пометка — запись для
вас: агент прочитает её вместе с запретом, но сама она ничего не
обеспечивает. Проверка: если удалить строку из этого файла,
действует ли запрет? Нет — `[окно]`; да — `[вызов]` или `[среда]`.

* `[окно]` — только текст в окне контекста модели; действует на слово;
* `[вызов]` — ведущее приложение проверяет вызов до исполнения: инструмента
нет в списке, аргумент не проходит проверку, действие требует подтверждения;
* `[среда]` — механизм среды: права доступа, отдельная копия, инвариант с откатом.
- Не изменять файлы в `data/`; перед запуском человек устанавливает атрибут «только чтение» для исходных файлов. `[среда]`
- Не изменять `checks/check.py`; файл проверки будет защищён от записи атрибутом «только чтение». `[среда]`
- Не устанавливать пакеты, не обращаться к сети и не запускать команды вне этого проекта. `[окно]`

## 5. Протокол работы

Режим работы: ReAct. Сначала изучи `AGENTS.md` и исходные данные, затем создай только два файла из раздела 0. После каждого изменения результата запускай `python checks/check.py`. При ошибке изучи сообщение и исправь только файлы результата; после двух неудачных проверок подряд остановись и доложи. Перед завершением покажи человеку `git status` и `git diff`; сам не коммить.

## 6. Память

Не переписывай существующую историю в `diary.md`. После прогона добавь запись: запрос, созданные файлы, результат проверки и ее код. Коммит делает человек после просмотра изменений.

## 7. Остановка и эскалация

* Бюджет эпизода: не более 15 шагов, 100 000 токенов или 20 минут.
* При исчерпании бюджета: отчёт — что сделано, что нет, где остановились.
* Остановись и спроси человека, если данные не соответствуют описанию, для выполнения цели нужно изменить входные данные или проверку, либо задача допускает несколько существенно разных трактовок.
* Если проверка не проходит дважды подряд по одной причине — остановись и
опиши причину.
